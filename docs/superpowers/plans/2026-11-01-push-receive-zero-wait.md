# Push-based, Non-blocking Syphon Receive Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Remove the per-frame synchronous GPU wait and the poll latency from the macOS shared-texture receive path, keeping it zero-copy (GPU-only).

**Architecture:** Syphon's `newFrameHandler` (background thread) stages each frame into a free slot of a 3-slot IOSurface ring, commits without waiting, and in the command buffer's completed handler hands a retained IOSurface to Rust, which forwards it to JS through a napi `ThreadsafeFunction`. The renderer's `createSharedTextureReceiver` subscribes to that push stream on macOS and delivers latest-wins. The existing poll API (`receiveSharedTexture`) and Windows behavior stay unchanged.

**Tech Stack:** Objective-C++ / Metal / Syphon, Rust napi-rs 2 (`napi8`), TypeScript + vitest, Electron 40.

**Spec:** `reports/2026-11-01-hot-path-baseline.md` (measurements + target list). User constraint: zero-copy is mandatory.

## Global Constraints

- Zero-copy: no CPU readback/upload anywhere on the paths touched. The single GPU→GPU staging copy stays (Syphon recycles its pool surfaces).
- A surface is never handed to JS before its staging command buffer has completed.
- Handle ownership contract is unchanged: every IOSurface handed to JS carries exactly one CFRetain owned by the caller, released by Electron's imported texture or by `closeNativeHandle()`.
- `receiveSharedTexture()` poll path, its return codes, and all Windows code stay behaviorally unchanged.
- Repo rules: arrow functions only, no `let`, no `forEach`, no `!`, no `any`, neverthrow `Result` never crosses a public API, `pnpm lint && pnpm typecheck` must pass, no commits by the implementer (the user commits).

## Review Focus

- Receiver `stop()` while a staging command buffer is in flight → no callback after stop, no use-after-free, in-flight surface released.
- All 3 ring slots still held by Electron (slow renderer) → frame dropped natively, no slot overwritten while imported.
- Frame size/format change mid-stream → ring slots reallocated, the first frame at the new size is delivered (not dropped).
- Push frame arrives while a previous `sendSharedTexture` is still pending → older pending frame's handle closed, newest delivered after the in-flight send settles.
- `onSharedTexture` called twice, or after `stop()` → replaces the callback / throws "receiver has been stopped"; never leaks the old TSFN.

- JS surface identical to Task 1: `TextureReceiver.onSharedTexture(cb | null)`; frames use the existing Windows `SharedTextureFrame` encoding (fresh duplicated NT handle, `pixelFormat` from `dxgi_format_to_pixel_format`).

Design decisions:
- Ring: 3 NT-shared staging textures (`SHARED_NTHANDLE | SHARED`, same desc as `ensure_nt_staging`), each with its own cached NT handle and its own last-handed-out duplicate value.
- Slot "held" check (Windows analogue of `CFGetRetainCount == 1`): a slot is held while the last duplicate handed out for it still refers to that slot's texture — `CompareObjectHandles(lastDup, slotCachedHandle)` (kernelbase, Win10 1607+). Electron closes the duplicate on release; a reused handle value pointing elsewhere compares FALSE ⇒ free. False "held" only causes a conservative drop.
- Completion (analogue of Metal's completed handler): after `CopyResource` into the slot, `End()` a `D3D11_QUERY_EVENT` and `Flush()`; deliver only once `GetData(query, …, D3D11_ASYNC_GETDATA_DONOTFLUSH) == S_OK`.
- Push driver: one native worker thread per receiver while a callback is set. Loop: `refresh_sender` → `frameCount->GetNewFrame()` → pick slot (drop on -1) → `CheckTextureAccess` / `CopyResource` / `AllowTextureAccess` → event query → poll query until done → `DuplicateHandle` the slot's cached handle → callback. When no new frame, wait ≈1 ms (`WaitForSingleObject` on a stop event with 1 ms timeout, `timeBeginPeriod(1)` scoped to the thread's lifetime). Dimension/format change reallocates the ring and still delivers that frame.
- Threading: the worker is the only user of the receiver's immediate context while push is active; additionally enable `ID3D10Multithread::SetMultithreadProtected(TRUE)` on the receiver device so a concurrent poll call cannot corrupt the context.
- Teardown: `set_frame_callback(NULL)` and destroy signal the stop event and `join` the worker before releasing slots; no callback after return. If the TSFN call cannot be queued, the Rust side closes the duplicate via the existing `close_shared_handle`.
- The existing poll path (`spout_receiver_receive_shared_texture`, single `ntStaging`) is unchanged.
